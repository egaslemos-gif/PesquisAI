# Regras de Versionamento e Cache (Guia do Investigador)\n\n## Política de Atualização da Versão Global (APP_VERSION)\n- A constante window.APP_VERSION em index.html deve ser alterada **Apenas** quando o Core (JavaScript principal, CSS ou infraestrutura comum) for modificado.\n- A alteração da APP_VERSION destrói o benefício da cache (CDN) para toda a aplicação. Portanto, evite incrementá-la por motivos triviais.\n\n## Política de Atualização de Versões de Módulos (assetVersion)\n- Para atualizações específicas de um módulo (ex: alterações num prompt, num checklist, ou num ficheiro the knowledge de um módulo), deve-se incrementar a versão e a assetVersion **apenas** no ficheiro module.json afetado (ex: WF-INV/module.json).\n- O ModuleLoader tratará de usar o manifest.assetVersion de forma independente, descarregando novamente apenas os recursos (prompts.js, steps.js, etc.) pertencentes a esse módulo, e preservando a eficiência da cache para todos os outros componentes da aplicação.\n\n## Regras de Proteção do Core Engine\n### Regra 3\nNenhuma alteração ao Core poderá ser feita para resolver um problema que possa ser resolvido através de assets do módulo.\n\n### Regra 4\nAntes de alterar qualquer componente do Core, confirmar que o problema não pode ser resolvido por:\n- Prompt\n- Knowledge\n- Checklist\n- Workflow\n- Configuração\n\n### Regra 5\nA IA nunca deve otimizar diretamente uma equação de pesquisa antes de confirmar que o investigador compreende a estratégia conceptual que lhe deu origem. Sempre que possível, deve privilegiar perguntas que obriguem o utilizador a justificar escolhas metodológicas (conceitos, sinónimos, bases de dados e critérios) antes de sugerir alterações técnicas.\n
